Detailed Functional Interaction of Components

1) MPU6050 → Impact Sensing Layer

The MPU6050 continuously streams acceleration and gyroscope values. The ESP32 polls or receives this data at a fixed sampling interval and applies threshold logic to detect high-impact signatures. Filtering and basic debounce timing help reduce false positives from normal vibrations or sudden braking.

2) ESP32 → Decision & Control Layer

ESP32 is the orchestration core. It evaluates sensor patterns, confirms crash likelihood, and controls downstream modules. Once trigger conditions are met, ESP32 transitions from monitor mode to emergency mode, initiates GPS acquisition, and then activates GSM notification logic.

3) NEO-6M GPS → Localization Layer

After a confirmed impact, ESP32 requests current coordinates from the NEO-6M. If a valid GPS fix is available, latitude/longitude are parsed and packaged into a human-readable message format. If fix is delayed, retry windows can be used before fallback messaging.

4) SIM800L GSM → Emergency Communication Layer

The SIM800L receives AT commands from ESP32 over serial. ESP32 first sends SMS (with coordinates and alert text), then optionally places a short emergency call to predefined contacts or services. This dual-channel method increases probability of successful notification.

5) End-to-End System Behavior

In normal mode, only sensing and monitoring are active. In emergency mode, the system escalates in sequence: crash detect → GPS acquire → SMS send → call trigger. This modular flow makes the prototype easier to test and tune for reliability in a university demonstration environment.
